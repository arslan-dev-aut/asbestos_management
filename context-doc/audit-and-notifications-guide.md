# Audit Logging & Notifications Guide

## Overview

All automations should include:
1. **Notifications** — Slack and/or Teams alerts on automation success, partial failure, or complete failure
2. **Audit logging** — Persistent execution logs in Cosmos DB (MongoDB API) via `AuditManager`

## Notification Decorators

Pre-built decorators in `joblogic_sdk.notifications` wrap async processing functions and automatically send alerts based on the outcome.

**Note:** Notification decorators do **not** automatically write audit log entries. Use the `@audit_log` decorator separately for audit logging.

### Slack Notifications

```python
from joblogic_sdk.notifications import slack_notification
from joblogic_sdk.models import ExecutionResult

@slack_notification(automation_name="My Auto", automation_code="MY-AUTO")
async def process(tenant_id: str) -> ExecutionResult:
    # ... automation logic ...
    return ExecutionResult(execution_time="...", read_count=10, create_count=5)
```

**Alert routing:**
| Outcome | Webhook |
|---------|---------|
| `failure_count == 0` | `SLACK_SUCCESS_WEBHOOK` |
| `failure_count > 0` | `SLACK_PARTIAL_FAILURE_WEBHOOK` |
| Exception raised | `SLACK_FAILURE_WEBHOOK` |

### Teams Notifications

```python
from joblogic_sdk.notifications import teams_notification

@teams_notification(automation_name="My Auto", automation_code="MY-AUTO")
async def process(tenant_id: str) -> ExecutionResult:
    ...
```

Posts to a single `TEAMS_WORKFLOW_URL` with an `is_success` flag (1 = success, 0 = failure).

### Stacking Decorators

Notification and audit decorators can be combined:

```python
from joblogic_sdk.notifications import slack_notification, teams_notification
from joblogic_sdk.audit import audit_log

@slack_notification(automation_name="My Auto", automation_code="MY-AUTO")
@teams_notification(automation_name="My Auto", automation_code="MY-AUTO")
@audit_log(automation_name="My Auto", automation_code="MY-AUTO")
async def process(tenant_id: str) -> ExecutionResult:
    ...
```

## ExecutionResult Model

Defined in `joblogic_sdk.models`:

| Field | Type | Description |
|-------|------|-------------|
| `execution_time` | `str` | Timestamp or duration |
| `read_count` | `int` | Records read |
| `create_count` | `int` | Records created |
| `update_count` | `int` | Records updated |
| `delete_count` | `int` | Records deleted |
| `failure_count` | `int` | Failed operations (triggers partial-failure if > 0) |
| `no_op_count` | `int` | Records skipped |
| `custom_message` | `str` | Free-text context |
| `azure_blob_storage` | `str \| None` | Link to detailed log blob |

## Cosmos DB (MongoDB API) Audit Logging

Audit logs are stored in **Cosmos DB (MongoDB API)** via the `AuditManager` singleton. The connection is configured through environment variables.

### Initialization

Initialize the `AuditManager` at application startup (e.g., in a FastAPI `lifespan` event):

```python
from joblogic_sdk.audit import AuditManager

# In your FastAPI lifespan or startup event:
await AuditManager.initialize()
```

### Audit Log Decorator

Use the `@audit_log` decorator to automatically log execution results to the audit database. This decorator is **separate** from the notification decorators:

```python
from joblogic_sdk.audit import audit_log
from joblogic_sdk.models import ExecutionResult

@audit_log(automation_name="My Auto", automation_code="MY-AUTO")
async def process(tenant_id: str) -> ExecutionResult:
    # ... automation logic ...
    return ExecutionResult(execution_time="...", read_count=10, create_count=5)
```

Each execution creates a document with:
- `automation_name` and `action` (automation code)
- `status` — `success`, `partial_failure`, or `failure`
- All `ExecutionResult` counters (read_count, create_count, etc.)
- `error_message` — captured from exceptions on failure
- `environment` and `tenant_id`
- `timestamp` — UTC ISO-8601

### Manual Logging

For custom audit entries outside of the audit decorator (e.g., logging intermediate steps), use `AuditManager.get_instance().log()` directly:

```python
from joblogic_sdk.audit import AuditManager

audit = AuditManager.get_instance()
await audit.log("my_automation", {
    "tenant_id": tenant_id,
    "action": "processing_started",
    "status": "success",
    "details": {"input_count": 50},
})
```

### Querying Audit Logs

REST endpoints are available at:

- `GET /api/audit/logs` — List logs with optional filters:
  - `automation_name`, `tenant_id`, `status` (filter)
  - `from_date`, `to_date` (ISO-8601 date range)
  - `page`, `page_size` (pagination, default 50)
- `GET /api/audit/logs/{id}` — Single log entry by ID
- `GET /api/audit/stats` — Summary counts by status and automation name

Via the backend API: `GET /audit/logs`, `GET /audit/logs/{id}`, `GET /audit/stats`

### Document Schema

Each audit log document in Cosmos DB contains:

```json
{
    "_id": "<auto-generated>",
    "automation_name": "my_automation",
    "tenant_id": "<tenant-guid>",
    "action": "MY-AUTO",
    "status": "success",
    "execution_time": "2.5s",
    "read_count": 10,
    "create_count": 5,
    "update_count": 0,
    "delete_count": 0,
    "failure_count": 0,
    "no_op_count": 0,
    "custom_message": "",
    "error_message": null,
    "details": {},
    "environment": "production",
    "timestamp": "2026-04-06T12:00:00Z"
}
```

## Required Environment Variables

```env
# Slack
SLACK_ENABLED=true
SLACK_SUCCESS_WEBHOOK=https://hooks.slack.com/services/...
SLACK_FAILURE_WEBHOOK=https://hooks.slack.com/services/...
SLACK_PARTIAL_FAILURE_WEBHOOK=https://hooks.slack.com/services/...

# Teams
TEAMS_ENABLED=1
TEAMS_WORKFLOW_URL=https://prod-XX.westeurope.logic.azure.com/...

# Audit Logging (Cosmos DB / MongoDB API)
AUDIT_MONGODB_CONNECTION_STRING=mongodb://<account>:<key>@<account>.mongo.cosmos.azure.com:10255/?ssl=true&...
AUDIT_DB_NAME=automation-audit
AUDIT_COLLECTION_NAME=audit_logs

# Common
APPLICATION_ENVIRONMENT=development
```
